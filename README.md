# 診所庫存管理系統

單一診所、依部門分庫別的庫存系統：進貨（含發票與金額）、耗用登記、庫存與批號效期、盤點、調撥、報表。

## 功能

| 頁面 | 說明 |
| --- | --- |
| 首頁 | 需補貨品項、效期提醒、本月耗用與進貨金額、待入庫／待驗收、未對發票、未付金額 |
| 耗用登記 | 掃條碼或輸入料號，預設先到期先扣；可指定批號。允許負庫存，但會提示 |
| 進貨單 | 批號、效期、數量、贈品、單價、金額（使用者輸入，不自動加稅）、可直接填發票 |
| 待採購清單 | 記下要訂的品項；下單後清除，或轉成「待入庫」進貨單。上方「補貨建議」列出不到 1 個月用量的品項，建議補到 3 個月（扣掉在途），勾選即可加入 |
| 匯入 HIS 耗用 | 上傳方鼎「藥品耗用統計表」（Excel／CSV／純文字），自動對應品項、扣庫、記錄實收金額與價別（健保／自費／贈送），可撤銷 |
| 統計分析 | 金額總覽（成本、收入、毛利、價別分布、12 個月趨勢）、品項耗用分析（與前期比較、ABC 分類、可用天數）、庫存健康度（可用月數、周轉率、近效批號用不用得完、呆滯品項） |
| 驗收開關 | 系統設定可開關。開啟時進貨單先「待驗收」，驗收後才入庫 |
| 發票 | 一張進貨單一張，或月結一張對多張進貨單；記錄已付／未付 |
| 庫存總覽 | 各庫別庫存、1/2/3 個月安全量狀態、庫存金額、最近效期，可一鍵加入待採購 |
| 流水帳 | 每個品項的批號庫存與進出紀錄、結存 |
| 庫別調撥、盤點 | 部門間移轉（保留批號效期成本）；盤點完成自動產生調整紀錄 |
| 報表 | 耗用（日／週／月／季／年，數量或金額）、進貨、庫存金額、效期，皆可匯出 Excel |
| 主檔 | 品項、供應商、類別（可自訂）、庫別（部門）、使用者（管理員／一般人員） |
| 操作紀錄 | 管理員可查誰在什麼時候新增、修改、刪除了什麼（含修改前後的值），可依人員、功能、日期、關鍵字篩選 |
| 我的帳號 | 每個人可自己修改密碼（側邊欄左下角點自己的名字） |
| 部門權限 | 在「使用者」頁面可對每個人、每個庫別設定「可看可改／只能看／不開放」。預設全部開放；管理員不受限 |
| 各部門自己的資料 | 品項、供應商可設「所屬部門」（留空＝全診所共用）和分類；清單預設看自己部門＋共用的，只有該部門可改的人能修改。發票的部門跟著它對應的進貨單；勾選「行政」的人可處理所有部門的發票 |
| 手機相機掃碼 | 進貨、耗用、調撥、待採購、盤點和品項的條碼欄都有相機按鈕，用手機瀏覽器開啟系統即可掃，不用安裝 App 或配對（需 https）。掃到系統不認得的條碼時，可當場選品項，系統會記住 |
| 每日提醒信 | 每天早上 8 點寄出各部門庫存不足、近效期、還沒入庫的進貨單。收件人與開關在「系統設定」，可預覽內容、寄測試信 |

安全量：品項可在各庫別手動設定每月用量；沒設定時依最近 90 天（可在系統設定調整）的耗用自動計算。

## 技術

Next.js 15（App Router、Server Actions）、TypeScript、Prisma + PostgreSQL、Tailwind CSS 4。

庫存數量存在批號（Batch），每一筆變動都寫入異動紀錄（StockMovement），`source` 欄位預留給之後串接 HIS 自動扣庫。

## 本機開發

```bash
cp .env.example .env          # 填 DATABASE_URL、AUTH_SECRET、SEED_ADMIN_PASSWORD
npm install
npx prisma migrate deploy     # 建立資料表
npm run db:seed               # 建立 admin 帳號、預設庫別與類別
npm run db:demo               # （選用）載入範例資料，正式環境不要執行
npm run dev                   # http://localhost:3000
```

測試：`npm test`（庫存規則單元測試）、`npm run lint`（型別檢查）。

## 部署（雲端）

建議：Vercel（網站，Pro 方案）＋ Neon（PostgreSQL，從 Vercel Marketplace 加入，區域選 Singapore）。

1. 用診所專用的 email 註冊 Vercel，升級 Pro。
2. 在 Vercel 的 Storage／Marketplace 加入 Neon，會自動設定 `DATABASE_URL` 與 `DATABASE_URL_UNPOOLED`。
3. 匯入這個 GitHub repo，另外設定環境變數：
   - `AUTH_SECRET`：一串長亂碼（例如 `openssl rand -base64 32` 的結果）
   - `SEED_ADMIN_PASSWORD`：第一個管理員 `admin` 的密碼（至少 8 字元）
   - `LOAD_DEMO_DATA=true`：只在試用時設定，會載入範例品項與耗用紀錄。正式環境不要設
4. 部署。每次部署會自動執行 `vercel-build`：建立／更新資料表，第一次部署時建立 admin 帳號與預設庫別、類別。
5. 用 `admin` 登入，到「系統設定」改診所名稱，到「使用者」建立人員帳號。

## 每日提醒信

收件人和開關在「系統設定 → 每日提醒信」。要真的寄出信，還需要在 Vercel 專案的 Settings → Environment Variables 加上：

| 變數 | 說明 |
|---|---|
| `RESEND_API_KEY` | 到 [resend.com](https://resend.com) 註冊後建立的 API Key（免費方案每天 100 封） |
| `CRON_SECRET` | 自己取一串長的亂碼。Vercel 每天呼叫 `/api/cron/digest` 時會帶上它，避免別人亂觸發 |
| `MAIL_FROM`（選填） | 寄件人，例如 `庫存提醒 <stock@your-domain.com>`。需要先在 Resend 驗證網域；沒填時用 Resend 的測試寄件人，只能寄到註冊 Resend 的那個信箱 |
| `APP_URL`（選填） | 信裡「打開庫存系統」的網址 |

加完後重新部署一次。排程寫在 `vercel.json`（UTC 00:00，也就是台灣早上 8 點；Vercel 免費方案的排程可能晚幾十分鐘執行）。沒設定 `RESEND_API_KEY` 時系統不會寄信，其他功能不受影響。

## 忘記密碼

- 一般人員忘記：請管理員到「使用者」頁，在那個人的列填新密碼後儲存。
- 管理員忘記：如果還有另一位管理員，請對方用同樣方式重設。只有一位管理員時，到 Vercel 專案的 Settings → Environment Variables 新增 `RESET_ADMIN_PASSWORD`（8 個字以上的新密碼），到 Deployments 按 Redeploy，之後用帳號 `admin` 和這組新密碼登入。登入後請把這個變數刪掉，並到「我的帳號」改成自己的密碼。
